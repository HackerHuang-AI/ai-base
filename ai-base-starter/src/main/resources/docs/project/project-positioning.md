# ai-base 项目定位

## 一、平台整体模块划分

AI 智能能力管理平台按用户工作台、运营控制面、基础域、运行时引擎和治理分析域拆分。下表只说明职责，建设状态由各模块自己的定位文档维护。

| 模块 | 平台职责 |
| --- | --- |
| `ai-base` | 用户、个人空间、企业租户、组织及租户侧角色、菜单、权限基础域（非运营角色） |
| `ai-operations` | 独立运营身份与权限、平台初始化编排与运营配置 |
| `ai-admin-gateway` | 用户租户入口、认证、路由与追踪 |
| `ai-operations-gateway` | 无租户运营入口、认证、路由与追踪 |
| `ai-admin-web` | 用户 AI 工作台兼企业智能管理平台 |
| `ai-operations-web` | 运营控制台 |
| `ai-agent` | 多 LLM 平台协议适配 |
| `ai-mcp` | 内置工具与外部 MCP Server 接入 |
| `ai-orchestration` | Agent 任务编排与 ReAct 循环 |
| `ai-memory` | 会话上下文与长期记忆 |
| `ai-knowledge` | 知识库与 RAG |
| `ai-eval` | 模型、Agent 及其调用质量评测 |
| `ai-experiment` | 实验分流与版本对比 |
| `ai-analysis` | 传统规则扫描与 AI 代码分析 |

## 二、项目背景与定位

`ai-base` 是用户侧基础域服务，面向 `ai-admin-web` 的个人 AI 工作台和企业智能管理能力。用户通过 `ai-admin-gateway` 访问本服务；运营身份与运营角色、菜单、权限归 `ai-operations`，不与本模块的用户租户体系混用。

个人空间与企业租户提供资源归属和隔离基础。用户无需加入企业即可在个人空间建设 Agent；租户级资源以 `tenant_id` 隔离，用户私有资源还应关联 `user_id`。切换或加入企业不能自动公开个人资源。

本模块不负责模型调用、Agent 设计及版本存储、工具执行、RAG 或会话记忆，只提供身份、空间、成员关系和权限基础；具体业务资源及其访问校验由对应领域模块维护。

## 三、本模块功能定位

- 管理全局用户、登录身份及后续企业 SSO 身份映射；
- 管理个人空间、企业租户、成员关系、空间选择与切换，以及企业入驻相关基础能力；
- 管理组织架构、岗位及用户侧角色、权限和菜单，不承载平台运营账号的权限体系；
- 签发、查询和撤销 `clientType=usr` 的 Redis 会话，保存用户与当前空间上下文；
- 为其他模块提供 `tenant_id`、`user_id`、成员资格和权限校验基础，不以“属于企业”替代用户私有资源授权。

## 五、请求上下文与职责边界

用户侧链路为 `ai-admin-web` → `ai-admin-gateway` → `ai-base` 及各用户业务模块。前端通过 `X-Tenant-Id` 表达当前空间，用户网关校验后转换为可信 `X-Internal-Tenant-Id`；下游不直接信任客户端伪造的内部身份头。

调用链首段由实际入口网关写入：用户侧为 `X-Call-Chain: limit=<maxCallChainHops>,length=<maxCallChainLength>;ai-admin-gateway`，运营侧为相同限制格式加 `ai-operations-gateway`。服务收到 HTTP 或 Dubbo 调用后追加自身应用名，并按首段限制校验；策略由两个网关各自的 Nacos 配置维护。

运营链路不携带租户登录身份；运营服务受控调用本模块时，应通过服务契约明确目标对象和授权，不伪装为租户用户。个人 Agent 的主动分享、企业市场下载和发布者版本更新由业务模块落实，本模块提供身份与归属基础；企业任务下发及司库接入后续设计，Agent 建设权不替代企业系统操作授权。

异步任务需要显式调用 `TraceContextSupport.wrap(task)` 或 `TraceContextSupport.wrap(callable)`，包装器只在任务执行期间恢复 `RequestContext` 与 MDC，现有线程池不会被自动改造。定时任务使用 `runScheduled` 或 `callScheduled` 建立无用户身份的新根上下文；其调用链不携带网关限制首段。

## 六、主要技术栈

| 功能 | 关键技术栈 |
| --- | --- |
| 基础身份与权限数据 | MySQL、Flyway、MyBatis-Plus |
| 用户登录与会话 | Redis Opaque Session、身份认证策略 |
| SSO 与跨服务身份上下文 | 企业 SSO（待接入）、Dubbo Triple、Nacos |
| Web 基础治理 | Spring MVC Interceptor、MDC、TraceId、显式异步上下文包装 |

## 七、后续建设方向

- 与用户工作台联调个人/企业空间选择、身份信息、菜单权限和服务端退出，完善登录使用闭环；
- 完善企业组织、成员、角色和权限管理，为各业务模块提供稳定的服务契约；
- 为个人私有资源、企业共享资源和企业业务系统接入提供明确的归属与授权基础，不在本模块实现 Agent 业务管理；
- 接入生产短信与企业 SSO，完善身份生命周期和审计。
